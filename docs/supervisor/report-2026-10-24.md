### Internal contradiction — The headless allow-list example admits write-capable git

*Surfaced by the Alignment checker.*

`docs/technical_design.md` § Cadence → *Headless invocation contract* gives the cadence run's command as `--allowedTools "Read,Bash(git *)"`, and the contract bullet beneath it commits the allow-list to *"read operations and read-only git invocations"*. `Bash(git *)` matches every git subcommand, including `commit`, `push`, `reset` and `checkout`. The same literal pattern is repeated in `docs/epics/EPIC-011-autonomic-invocation.md` (AC#1, § Plan → *Tasks*, and § Plan → *Risks*).

This matters more than its size suggests, for two reasons. First, the same section says that until EPIC-011's launcher sets `SHANNON_SUPERVISOR_SCOPE` the PreToolUse write-guard is inert, *"so the path scope rests on `--allowedTools` alone"*: the allow-list is the only control in that window, and the example is looser than the contract. Second, EPIC-011 is the next supervisor Epic to be elaborated, and its acceptance criterion copies the loose pattern, so an implementer following AC#1 literally would ship an unattended run able to push to a public remote. The shipped checkers already show the right shape (`Bash(git log:*)`, `Bash(git diff:*)`, `Bash(git status)`), so the fix is to align the example and EPIC-011 AC#1 with them, best done before EPIC-011's Gate 1.
